# 메뉴 근거 누락 시 배치 복원

가져오기에서 유효한 문서 근거가 있으나 MENU 근거 번호를 고르지 않은 경우를 제한적으로 복원한다. 공통 지침·JSON 형식·5depth 구조는 유지한다.

## 자동 복원 조건

- 새 가져오기이며, 고정 자료의 원문 인용 검증을 먼저 통과해야 한다.
- LLM의 menuPath가 비어 있지 않고 실제 수집된 MENU의 전체 경로와 정확히 일치해야 한다. 번역·동의어·부분 일치는 사용하지 않는다.
- 선택된 DOCUMENT 인용에 해당 메뉴명이 독립된 단어로 있어야 한다. 메뉴명이 반복되는 다른 경로나 여러 근거 후보가 있으면 복원하지 않는다.
- 기존에 상충하는 메뉴 근거를 선택했거나 MENU_GROUP만 일치하면 복원하지 않는다.
- 메뉴 근거를 추가해도 총 8개를 넘지 않아야 한다. 원본 문서 근거를 버려 자리를 만들지 않는다.

조건에 맞으면 관찰된 메뉴의 실제 ID·원문을 연결하고, 사용자가 명시적으로 제외한 행이 아니라면 포함한다. `connectionStatus=PROPOSED`, `reviewStatus=NEEDS_REVIEW`를 유지한다. 메뉴명 일치는 기능 동작·의미적 연결을 검증한 결과가 아니다.

## 검토·보존

`placementReview`에 최초 제안 경로·판단 방식·문서/메뉴 sourceId·사유를 보존한다. 저장·명시적 제외 시 이력을 유지하고, 사용자가 경로를 변경하면 현재 배치 판단을 다시 기록한다. UI에서 자동 배치 표시와 판단 근거를 확인할 수 있다. 포함 기능 수와 메뉴 구조 수를 별도로 보여 준다.

## 기존 작업

이미 구버전 가져오기에서 경로가 지워진 123행은 원래 LLM 경로를 복원할 수 없다. 기존 초안을 임의로 변경하지 않으며 원본 LLM JSON을 다시 가져와야 새 규칙을 적용할 수 있다. 원본 경로도 비어 있거나 문서 근거에 메뉴명이 없다면 계속 배치 필요로 남는다.

## 검증

`MenuPlacementRecoveryTest`: 외부 근거 번호 응답→복원→검증 연결, 정상 배치, 빈/비일치 경로, 무관한 인용, 상충 근거, 중복 메뉴명, 근거 개수 한도, 허위 인용 거부, 명시적 제외·저장 이력 유지.

기존 Validator·외부 LLM 계약·Excel·TC API 통합 테스트와 프런트 빌드, 브라우저의 포함 선택·취소·저장·승인·근거 보존 검증을 함께 수행한다.
