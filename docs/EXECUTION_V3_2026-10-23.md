# Qwen 8B 시험 수행 개선·검증 결과

검증일: 2026-10-23. 개발 서버 반영 완료. 전체 TC 검증 완료를 의미하지 않습니다.

## 변경 내용

- 시험 수행 모델을 `qwen3:8b`로 변경했습니다. 실제 로딩 모델 ID는 `500a1f067a9f`, 컨텍스트는 8192이며 현재 장비에서는 CPU로 실행됩니다. 문서 생성용 모델 설정과는 별개입니다.
- 승인된 메뉴 경로·수집 정보와 현재 DOM의 유일한 탐색 요소를 대조해 코드로 이동합니다. 수집 ID가 없는 업로드 메뉴도 승인 메뉴 경로로 연결합니다. 찾지 못하거나 모호한 조작만 Qwen에 요청합니다.
- 조회 TC는 대상 본문의 제목/경로, 로딩 완료, 본문 존재를 확인한 증거로 수행 완료를 기록합니다. 메뉴를 다시 누르는 일을 수행으로 요구하지 않습니다.
- 동일한 메뉴를 반복해서 클릭하는 계획을 실행 전에 차단합니다. 시계·실시간 카운터가 변해도 같은 탐색을 반복하지 않습니다. 조작 입력과 이력을 줄여 추론 부하도 줄였습니다.
- 시험 화면에 Qwen/프로그램별 계획, 대상, 수행 기록을 표시합니다. 입력값은 공개 추적 정보에서 제외합니다.
- 명시된 단일 클릭 또는 조회에서 모든 기대 문구를 본문과 직접 대조할 수 있을 때만 코드로 P/F를 판정합니다. 사이드바 문구로 통과시키지 않으며, 일반 의미 판정은 Jev와 기존 신뢰도 기준 0.90을 유지합니다. 판정 주체를 UI에 구분합니다.

## 실제 브라우저·Qwen·Jev 결함 주입 시험

일회성 합성 사이트에서 실제 Playwright, 실제 Qwen 8B, 실제 Jev를 사용했습니다. 정상·결함의 기대 결과는 실행 전에 고정했습니다.

|시험|기대|결과|Qwen 호출|소요 초|
|---|---|---|---:|---:|
|정상 조회|P|P|0|1.63|
|본문 결함 조회, 사이드바에는 정상 문구|F|F|0|1.57|
|정상 버튼 동작|P|P|1|17.64|
|결함 버튼 동작|F|F|1|16.78|

4건 모두 기대와 일치했습니다. 두 버튼 시험은 실제 모델이 클릭 대상을 선택했고 각각 한 번만 클릭했습니다. **최종 P/F 주체는 명시적 문구를 검증한 코드입니다.** Jev 원응답도 보존했으나 이 결과를 Jev 단독 판정 성공으로 해석하면 안 됩니다. 정상 2건과 결함 2건은 제한된 표본이며 일반화 성능의 증명은 아닙니다.

## 남은 개선 사항과 다음 순서

1. TC 생성 시 “목적에 맞게 동작함”을 화면별 확인 가능한 항목으로 구체화해야 합니다. 예: DAG 목록의 이름·상태 열, 조회 권한, API 오류 유무, 표시된 데이터의 근거. 문서·수집 자료로 알 수 없는 정답을 임의 생성하면 안 됩니다.
2. 검색·필터·등록·파일·권한 등은 기능별 실행 계약(사전 상태, 입력, 조작, 대기, 기대 결과, 복구)을 추가해야 합니다. 이번 명시적 단일 클릭 규칙을 다단계 시험의 완료로 확장하지 않았습니다.
3. Jev의 의미 판정은 근거 연결과 별도 정답 세트로 보정·평가해야 합니다. 8B 전환만으로 신뢰도가 해결되지는 않았습니다. 필요하면 이후 외부 모델을 동일 정답 세트로 비교해야 합니다.
4. CPU 환경에서 긴 입력의 Qwen 추론은 여전히 느립니다. 이번에는 불필요한 호출을 없앤 효과가 컸으며, 모든 상호작용이 빨라졌다는 의미는 아닙니다.
5. 본문이 iframe에만 존재하거나 화면명과 메뉴명이 다른 제품은 추가 화면 매핑이 필요할 수 있습니다. 그런 경우 본문 검증을 우회해 P로 처리하지 않습니다.
