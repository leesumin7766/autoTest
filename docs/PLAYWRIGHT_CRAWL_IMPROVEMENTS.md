# Playwright 화면·메뉴 수집 개선 정리

## 목적

URL은 화면의 속성 중 하나이며 페이지의 고유 식별자가 아니다. 서로 다른 메뉴가 같은 주소로 이동하거나 SPA·탭·iframe 내부 내용만 바뀌는 제품을 지원한다. 메뉴, 클릭 이동, 결과 화면을 각각 보존한다.

## 변경 사항

| 영역 | 이전 | 개선 |
|---|---|---|
| 방문 판단 | URL별 한 번 | 메뉴 경로·종류·클릭 요소를 식별해 실제 클릭을 수행 |
| 화면 상태 | URL과 이미지 중심 | URL 상태의 해시, 선택 메뉴·탭, 표시 중인 iframe, 제목·본문·UI 구조의 상태 지문 |
| 메뉴 연결 | 같은 URL의 캡처를 자동 연결 | 해당 메뉴의 클릭 결과가 확인된 캡처만 연결 |
| 같은 URL의 여러 화면 | 합쳐질 수 있음 | 메뉴별 이동과 화면 상태를 별도 저장 |
| 여러 메뉴의 같은 화면 | 중복으로 해석할 수 있음 | 서로 다른 메뉴에서 같은 화면으로 이어지는 관계 허용 |
| 로딩 대기 | HTML과 네트워크 유휴 중심 | 표시 중인 iframe·주요 스피너·aria-busy·본문 구조 안정 확인 |
| iframe 내용 | 주로 바깥 문서 본문 | 표시 중인 허용 사이트 iframe의 본문·요소·링크 포함 |
| 계층 | 목록 위주 | ARIA section heading과 iframe 진입 경로를 상위 메뉴로 반영 |
| 버튼 | 링크 위주 탐색 | 탐색 영역의 메뉴·탭 버튼 클릭, 입력 폼·위험 작업 제외 |
| 로딩 미완료 | 정상 캡처로 오해 가능 | 진단 캡처로 표시하고 정상 근거에서 제외 |
| 페이지 나가기 확인 | 모든 대화상자 취소로 후속 이동이 막힐 수 있음 | `beforeunload`만 허용하고 일반 제품 확인창은 취소 |

## 수집 및 판정 흐름

1. 저장한 계정으로 로그인한다.
2. 표시 중인 화면·iframe에서 메뉴와 계층을 관찰한다.
3. 메뉴별 클릭 순서를 저장하고 시작 화면에서 순서대로 재현한다.
4. 이동마다 사용자 지정 대기 한도 안에서 화면 준비를 확인한다.
5. 캡처·iframe 본문·상태 지문과 이동 근거를 함께 저장한다.
6. 클릭 결과와 메뉴를 연결해 검토용 트리를 만든다.

‘최대 대기 시간’은 기존과 같이 기본 30초, 1~60초다. 전체 수집 시간·최대 화면 수·깊이 제한도 유지한다. 네트워크 통신이 계속되는 제품도 고려해 networkidle만으로 완료를 판단하지 않는다. 주요 로딩 표시가 없어지고 구조가 1초 안정된 상태를 확인하며, 최초 최소 1.5초를 관찰한다.

## 상태의 의미

- `CAPTURED`: 해당 메뉴 클릭 후 준비된 화면 또는 선택 상태를 확인했다. 기능 전체가 정상이라는 뜻은 아니다.
- `LOAD_TIMEOUT`: 로딩 대기 한도 안에 준비되지 않았다. 진단 캡처를 남기고 후속 탐색하지 않는다.
- `NO_STATE_CHANGE`: 클릭했지만 상태 변경이나 메뉴 선택을 확인하지 못했다. 정상 연결로 단정하지 않는다.
- `UNVISITED`: 메뉴는 발견했으나 한도·실패 등으로 화면 연결을 확인하지 못했다.
- `UNVERIFIED`: 이전 실행 결과로, URL은 있어도 클릭 근거가 없다.
- `GROUP`: 메뉴 계층을 표현하는 그룹이다.

메뉴트리는 URL이 같다는 이유로 항목을 삭제하지 않는다. 한 메뉴의 여러 결과는 `screens`에 보존한다. 수집 중단·깊이·시간 한도로 끝난 작업도 미확인 항목을 유지한다.

## 저장과 조회

- V18: `playwright_crawl_pages.navigation`에 메뉴 관찰 저장.
- V19: 같은 테이블의 `screen_state`, `nav_transition`에 상태와 이동 근거 저장.
- `playwright_crawl_jobs.crawl_result`: 로딩 미완료·이동 실패·변화 미확인·확인된 상태 수 및 실패 메뉴 목록.
- 기존 JPEG·본문·UI 요소·링크 저장은 유지한다. DB는 PostgreSQL `autotest`, Docker `db_data` 볼륨이다.
- `GET /api/submissions/{submission}/playwright-crawls/{job}/menu-tree`는 `captured-menu-tree-v2`를 반환한다. 소유권을 확인하며 다른 회원 결과는 조회할 수 없다.
- UI에서 메뉴별 연결 화면·진단 캡처·클릭 경로와 상태를 확인한다. 이전 데이터는 보존하며 클릭 근거는 재수집해야 생긴다.

## 검증

- Java: 86개 테스트 통과. 동일 URL의 서로 다른 메뉴 연결, 이전 URL 일치의 오판 방지, 로딩 미완료 구분, 소유권·범위 검증 포함.
- Chromium: 9개 테스트 통과. 같은 URL의 iframe 탭 두 개가 다른 화면 지문과 클릭 근거로 남는지, 지연 로딩 본문 대기, 1초 제한의 미완료 판정, 인증서 허용·로그인·쓰기 차단 포함.
- 페이지 나가기 확인이 있는 탭에서 다음 메뉴로 정상 이동하는 회귀 테스트 포함.
- 프런트엔드 빌드 통과. lint는 기존 React effect 경고가 남아 있다.
- DB custom-format 백업 후 V19 적용 및 서비스 정상 기동 확인.

## 실제 제품 검증

대상은 사용자 지정 `https://210.96.71.204:9090/`, 로컬 실행 위치는 `.206`이다. 비밀번호는 이 문서에 기록하지 않는다.

변경 전 실행 `5728e54c-dd3a-4699-acb5-fb065a5bb7df`는 16개 캡처와 38개 메뉴 노드를 저장했지만 Storage의 빈 화면, Networking/Services/Software updates의 로딩 화면, iframe 본문 누락, 계층 부족이 확인됐다.

개선 후 첫 실행 `65c224f0-54f2-4a15-ab77-24a86fabbd45`에서 주요 화면 16개가 READY로 저장됐다. Storage 디스크 목록, Networking 인터페이스, Services 서비스 목록을 캡처로 확인했다. Storage 본문은 바깥 메뉴 중심 304자에서 iframe 포함 1,159자로 늘었다. 메뉴는 `Global → System`, `Global → Tools` 계층으로 구분됐다. 이 실행의 하위 탭 재현 실패는 후속 재검증 대상으로 남겼다.

Services 하위 탭만 별도 재검증했을 때 Services·Targets·Sockets·Timers·Paths가 모두 READY/CONFIRMED로 수집됐다. 전체 경로에서만 실패한 원인은 Terminal 방문 후 페이지 나가기 확인을 취소한 데 있었다. `beforeunload`만 허용하도록 수정하고 회귀 테스트 및 전체 재실행으로 확인했다.

최종 실행은 `1880009a-c4a6-451e-b8dc-f45d63337a1e`이며 `COMPLETED / DONE`으로 종료됐다.

| 클릭 결과가 확인된 메뉴 | 20개 |
| 메뉴트리 노드 | 24개(그룹 포함) |
| 로딩 미완료 | 0개 |

Services·Targets·Sockets·Timers·Paths의 저장 URL은 모두 `https://210.96.71.204:9090/system/services#/`로 같았다. 각 탭은 서로 다른 `menuKey`, `screenKey`, 본문과 캡처로 보존됐다. Targets·Sockets·Paths 캡처의 실제 선택 탭과 목록도 직접 확인했다. URL이 같다는 이유로 메뉴나 캡처를 합치지 않는다.

이 결과는 캡처·탐색 검증이며 제품 기능의 합격 판정은 아니다. 상태 지문 21개가 업무 기능 21개를 의미하지도 않는다.

## 남은 한계

- 자동 판정은 제품의 모든 업무 데이터가 완전히 조회됐다는 보증은 아니다. 사용자 정의 로딩 표시·비표준 탐색 UI는 추가 지원이 필요할 수 있다.
- 상태 지문은 캡처 시점의 상태를 표현한다. 실시간 값이 바뀌면 달라질 수 있으므로 업무 화면의 영구 ID로 취급하지 않는다.
- CAPTCHA·MFA·접근 권한 상승, 가상화된 메뉴의 전체 스크롤, 복잡한 팝업은 별도 지원 범위다.
- 문서 기반 메뉴트리와 자동 병합하거나 TC 생성·승인에 자동 반영하지 않는다. 다음 연결 단계에서 기능리스트·매뉴얼 근거와 대조해야 한다.
