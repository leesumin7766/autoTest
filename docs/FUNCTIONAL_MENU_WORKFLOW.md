# 통합 메뉴트리 작성·검토·Excel 출력

## 사용 순서

1. 기능리스트·매뉴얼 업로드와 Jev 검증을 완료한다. 시험합의서는 선택이다.
2. 최신 Playwright 실행기로 화면을 수집한다. 상단·하단 메뉴도 관찰하며 관리 접근·삭제 등 위험한 항목은 실제 수행하지 않는다.
3. 화면 아래 **통합 메뉴트리 · 기능 설명 · Excel**에서 제품명과 완료된 수집 실행을 선택한다.
4. **통합 메뉴트리 자동 생성**을 누른다. 현재 LLM 설정을 사용하며 단계별 진행률을 표시한다.
5. 각 행의 분류·기능명·메뉴 설명·위치·근거를 검토한다. 행을 제외하거나 기능을 분리할 수 있다. 근거 버튼에서 원문 구간과 해당 캡처를 확인한다.
6. 초안을 저장하거나 **포함한 기능을 검토 완료·승인**한 후 승인 Excel을 다운로드한다. 편집한 승인본은 저장 시 다시 초안이 된다.

외부 LLM을 사용할 때는 **외부 LLM으로 작성 → 통합 프롬프트 만들기 → 응답 JSON 가져오기** 순서로 사용한다. 원문 전체와 기능 근거를 포함하므로 사용자가 내용을 확인하고 직접 전달한다. 프로그램이 외부 서비스에 자동 전송하지 않는다.

## 구성

- `ai-service/menu_templates/functional-v1/rules.json`: 작성 규칙, 5depth, 설명 문체, 위치·근거 원칙.
- `output.schema.json`: 구조화된 LLM 응답 형식.
- `examples.json`: 사용자 예시에 맞춘 조회·삭제 기능의 작성 예시. 실제 제품 정보로 사용하지 않는다.
- `ai-service/functional_menu.py`: Ollama 자동 생성, 원문 구간 선택, 검증 및 외부 프롬프트.
- `FunctionalMenuService`: 문서와 수집 실행 스냅샷, 비동기 작업, 버전·소유권 관리.
- `FunctionalMenuValidator`: 경로·설명·인용문·메뉴 연결 검증.
- `FunctionalMenuExcel`: 6열 Excel과 근거·검토 시트 출력.

추가 모델 학습은 하지 않는다. 기존 LLM에 규칙·예시와 고정한 제품 자료를 제공한다. 자동 생성 중에는 LLM이 원문 구간 ID를 선택하고 프로그램이 정확한 원문을 결과에 붙인다. 원문을 다시 작성한 인용문은 허용하지 않는다. 기능리스트에 명시된 주요 동작의 누락은 재시도 후 차단한다. 이는 모든 업무 의미를 자동으로 완전히 검증한다는 뜻은 아니다.

## 데이터와 판정

### 실제 웹 구조 우선 (web-first-v1)

새 작업은 Playwright가 관찰한 메뉴명·표시 순서·상위 그룹을 `webStructure`로 먼저 고정한다. 제품명은 1depth이며 문서나 모델이 새로운 2~4depth 그룹을 임의로 만들 수 없다. 예를 들어 화면에 `운영 > 실시간`이 있으면 그 경로가 분류 기준이다. 탭은 선택된 화면 메뉴 아래에 연결한다. 같은 URL이라도 메뉴 경로가 다르면 구분하며, 동일한 웹 경로의 반복 관찰은 구조에서 중복 제거한다.

`상단바`·`하단바` 그룹은 전역 header/banner 또는 footer/contentinfo 등 실제 영역이 관찰되고 `barConfirmed=true`일 때만 만든다. 본문 카드의 header나 좌측 바 아래쪽에 있다는 이유로 그룹을 만들지 않는다. 별도 그룹이 없는 테마·언어·사용자 메뉴는 독립된 메뉴 경로로 보존한다. 문서상 소속에 따른 보완은 화면과 모순되지 않는 기존 웹 경로를 선택해 검토·저장할 수 있다.

LLM은 관찰된 후보 메뉴에 기능 설명과 근거를 연결한다. 서버도 고정한 웹 경로를 재검증한다. 연결 위치를 확인하지 못한 문서 기능은 `placementStatus=UNASSIGNED`, 기본 포함 해제로 별도 배치 검토 목록에 남긴다. 화면에 존재하지 않는 메뉴가 있다고 단정하지 않으며, 사용자가 관찰된 경로를 골라 수동 배치한 경우 `MANUAL_PLACEMENT`로 구분한다.

문서 기능이 연결된 메뉴는 기능 행으로 출력하며, 아직 기능이 연결되지 않은 실제 메뉴는 `MENU_OBSERVATION` 구조 행으로 남긴다. 구조 행은 2~4depth에 실제 경로를 출력하고 5depth는 비워, 화면 메뉴를 억지로 최하위 기능으로 만들지 않는다. Excel 순서도 웹 구조를 따르며 위치 미확인 문서 기능은 본문 트리 대신 `배치 검토` 시트에 보존한다.

이전 수집의 그룹·영역을 소급해서 추정하지 않는다. 정확한 새 구조를 얻으려면 최신 실행기로 재수집 후 새 메뉴트리 작업을 시작한다. 기존 생성 결과와 승인본은 변경하지 않는다.

### 근거 자동 첨부와 부분 초안

자동 생성은 현재 입력 후보로 제공한 메뉴 키에 한해 해당 메뉴의 고정 근거를 프로그램이 첨부한다. 제공하지 않은 키는 연결을 해제하고 문서 근거를 유지한다. 인용문이 원문과 다르거나 현재 문서 구간의 근거가 없는 행은 정상 행으로 취급하지 않는다. `evidenceStatus=VALID`는 참조·인용의 형식적 검증, `connectionStatus=PROPOSED`는 의미적 연결이 아직 검토 전이라는 뜻이다. 근거를 자동 첨부했다고 연결 정확성을 확정하지 않는다. `NOT_LINKED`는 화면 메뉴 연결 미확인이며 실제 제품에 기능이 없다는 뜻이 아니다.

행 검증 실패는 오류 코드·입력 sourceId·재분할 위치·행 번호·생성 응답을 `output.issues`에 보존한다. 정상 행은 유지하고 다음 구간을 분석한다. 서비스 연결이 끊겨 계속 분석할 수 없으면 이미 처리한 행과 진행률을 부분 초안으로 보존한다. 화면에는 최대 100건의 진단과 전체 건수를 표시한다. 프로그램 로그에 문서 본문이나 모델 응답을 출력하지 않는다.

AI는 구간 처리 후 `ai-service/.runtime/functional-menu-jobs/`에 접근 제한된 체크포인트를 원자적으로 기록한다. 내부 인증이 필요한 `/api/v1/functional-menus/checkpoint/{jobId}`를 통해 TMS가 소유권을 확인한 작업의 결과를 가져와 DB에 보존한다. 진행 상태 조회 시에도 저장하며, 시간 초과·서비스 오류 발생 시 체크포인트를 회수한다. 명시적으로 취소한 작업은 늦은 결과로 다시 게시하지 않는다. 이는 새 작업이 실패 지점부터 자동 재개된다는 뜻은 아니다.

`completionStatus=PARTIAL`은 미확인 구간이 있는 부분 초안이다. 정상 행 수정·초안 Excel 다운로드는 가능하며, 전체 결과를 보완하기 전 승인 API와 버튼은 차단한다. 기존 외부 LLM JSON 가져오기로 완전한 결과를 보완할 수 있다. Excel 본문 6열은 유지하고 근거·검토 시트에는 참조 상태와 연결 상태, 미확인 구간 시트에는 진단을 표시한다.

메뉴와 기능은 구분한다. 수집한 메뉴의 `menuKey`와 기능의 `rowId`를 별도로 유지한다. 같은 URL의 메뉴·탭은 합치지 않으며 한 기능을 여러 메뉴·문서 근거와 연결할 수 있다. 자동 생성이 세부 기능을 제안하지 못한 실제 메뉴도 존재 근거 행으로 유지한다.

제품명은 1depth, `menuPath`는 2~4depth(최대 3개), `functionName`은 5depth다. 위치는 HEADER/FOOTER/SIDEBAR/CONTENT/UNKNOWN 속성으로 저장하며 상단·하단이라는 이유만으로 depth를 소모하지 않는다. 원본 수집 경로와 문서 위치는 근거에 보존한다. 불필요한 탐색 컨테이너 이름(Global/Local 등)을 제외한 분류는 검토 대상이다.

메뉴 설명은 '~을 조회하는 기능', '~을 설정하는 기능' 등으로 작성한다. 예:

| 1depth | 2depth | 3depth | 4depth | 5depth | 메뉴 설명 |
|---|---|---|---|---|---|
| 제품명 | 스케줄 | 스케줄 관리 | - | 스케줄 조회 | 작업의 스케줄 내역을 조회하는 기능 |
| 제품명 | 스케줄 | 스케줄 관리 | - | 스케줄 삭제 | 스케줄을 삭제하는 기능 |

내부 데이터에 `-`를 넣지 않는다. Excel에서만 빈 분류를 `-`로 출력하며, 완전한 상위 경로가 같은 연속 행만 세로 병합한다. 최하위 기능과 메뉴 설명은 병합하지 않는다. 값은 수식이 아닌 문자열로 기록한다. 긴 한국어는 줄바꿈과 행 높이를 조정한다.

확인 상태는 사용자 검토를 돕는 자료다:

- `SCREEN_OBSERVED`: 실제 메뉴 또는 화면에서 발견. 기능 동작 합격을 뜻하지 않는다.
- `DOCUMENT_ONLY`: 문서 근거만 있으며 실제 화면 연결을 확인하지 못함.
- `MATCH_PROPOSED`: 문서와 화면 근거를 함께 인용한 연결 제안. 의미적 일치는 사용자가 검토한다.
- `INCOMPLETE`: 인용한 화면에 로딩 미완료 상태가 있음.

모든 행은 검토 대상이다. `MOCK` 결과는 문서를 실제 분석한 결과가 아니며 최종 승인할 수 없다. 초안 Excel은 초안 이름·인쇄 푸터로 구분한다. 원본 인용은 편집 시에도 고정되며 기능 분리는 기존 행의 근거를 복사한다.

## 버전·안전·제한

- Java→AI 대용량 생성 요청은 HTTP/1.1을 사용한다. 서버의 HTTP/2 업그레이드 미지원으로 인한 요청 거부를 방지한다. 연결 오류·응답 대기 시간 초과·중단은 서로 다른 오류 코드로 표시한다.
- 수집 실패·미확인 항목은 입력 스냅샷의 경고에 남기며 생성 완료만으로 전체 메뉴가 검증됐다고 표시하지 않는다.

- V20의 `functional_menu_jobs`에 선택한 수집 실행, 문서 digest, 제품명, 규칙 버전, 입력 근거, 결과와 revision을 보관한다.
- GENERATING → DRAFT → APPROVED 흐름이며 실패·취소 상태도 보존한다. 서버 재시작 시 진행 중 작업은 INTERRUPTED로 닫고 결과를 덮어쓰지 않는다.
- 취소한 작업의 늦은 결과는 게시하지 않는다. 생성 서비스는 요청 연결이 끊기면 진행 중 LLM 호출을 취소한다.
- 문서 변경 후에는 승인·다운로드를 차단한다. 더 최신 수집이 있으면 안내하되, 기존 초안은 선택했던 실행을 유지한다.
- revision이 다른 수정·승인은 충돌로 거부한다. 다른 회원의 작업·근거·Excel은 조회할 수 없다.
- 입력은 최대 5,000개 근거·10MiB, 출력은 최대 2,000개 기능 행이다. 한도를 넘으면 명시적으로 중단하며 조용히 잘라내지 않는다.
- 자동 생성은 문서 전체를 구간으로 나눠 분석하고, 관련 메뉴·화면 구간을 검색해 문맥으로 제공한다. 화면의 데이터 목록 전체를 매번 기능으로 추출하지 않는다. 메뉴와 화면 버튼은 프로그램이 관찰 목록으로 보존한다. 문서와 연결되지 않은 본문 버튼은 기본적으로 포함을 해제해 두고 사용자가 검토 후 선택한다. 긴 자료는 시간이 걸리며 입력·출력 한도나 모델 품질 문제로 실패할 수 있다. 고정한 원문은 보존되므로 외부 LLM 경로로 이어갈 수 있다.
- 근거의 문서 위치는 추출 텍스트의 문자 범위다. 원본 PDF 페이지·Excel 셀 주소를 추측해 표시하지 않는다.
- 현재 기능은 메뉴트리 검토·Excel 출력까지다. 기존 TC 메뉴트리 승인 데이터나 TC 생성에 자동 반영하지 않는다.

## API

기본 경로: `/api/submissions/{submission}/functional-menu`, `X-Member-Id` 필요.

| 요청 | 기능 |
|---|---|
| GET `?job={id}` | 선택 작업·이력·완료 수집 목록 |
| POST `{crawlJobId,productName,mode:AUTO/EXTERNAL}` | 고정 입력으로 작성 시작 |
| POST `/{job}/prompt` | 외부 작성용 규칙·예시·자료·스키마 |
| POST `/{job}/import` | `{revision,rows}` 근거 검증 후 가져오기 |
| PUT `/{job}/draft` | `{revision,rows}` 수정 저장 |
| PUT `/{job}/approval` | `{revision,rows}` 사용자 승인 |
| POST `/{job}/cancel` | 생성 중단 |
| GET `/{job}/evidence?sourceId=...` | 고정한 원문 근거 |
| GET `/{job}/download?draft=true/false` | 초안 또는 승인 Excel |

AI 내부 API는 `/api/v1/functional-menus/generate`, `/prompt`, `/progress/{jobId}`이며 기존 내부 토큰으로 보호한다. 문서·비밀번호·LLM 응답 본문은 로그에 출력하지 않는다.

## 이번 검증 결과

- Java 88개, 메뉴 생성 Python 7개, Chromium 9개 테스트 통과.
- 정확하지 않은 원문 인용 거부, 메뉴 연결 근거 확인, 수정 revision 충돌, 다른 회원 조회 차단, 문서 변경 시 다운로드 차단을 확인했다.
- Excel 6열, 상위 경로가 다른 동일 이름의 잘못된 병합 방지, `-` 처리, 수식 대신 문자열 기록을 확인했다.
- 현재 실제 Ollama 모델 `qwen3:4b`에서 검증용 문장의 스케줄 조회·삭제가 두 기능으로 생성되고 원문 인용 검증을 통과했다. 전체 실제 제품 메뉴트리를 승인한 결과는 아니다.
- 실제 `.204` 화면의 Limited access·Help·Session을 HEADER로 관찰했고 모두 `canExplore=false`로 확인했다. 최신 수집 결과부터 이 정보가 저장된다.
- DB 백업 후 V20을 적용했다. 기존 수집·문서·승인 결과는 보존했다.
