# 시험 실행의 최초 URL 확인

5번 시험 실행에서 처음 실제 브라우저를 여는 TC에만 적용한다. 2번 화면 수집과 후속 TC의 정상적인 화면 이동에는 적용하지 않는다.

1. 처음에는 자동 로그인과 Basic 인증 정보를 적용하지 않은 새 브라우저 세션으로 시작 URL을 연다.
2. 요청 URL과 실제 URL을 비교한다. 원점, 경로, 쿼리와 hash를 비교하되 마지막 슬래시 차이는 무시한다. FORM_AUTO 제품이 같은 사이트의 로그인 화면으로 이동하고 계정 입력·비밀번호·로그인 제출 요소가 관찰되면 정상 인증 진입 리다이렉트로 구분한다. 예를 들어 NeoFlow의 / → /login은 정상 진입이고 / → /dashboard와 다르다. 요청/실제 URL과 이 구분을 모두 기록한다. URL이나 로그인 화면 확인은 TC 통과 증거가 아니다.
3. 다르면 현재 URL·관찰된 인증 상태·세션 재생성 횟수를 Qwen에 전달해 초기 복구만 판단한다. 짧은 RESET_SESSION/STOP 응답을 사용하며 일반 TC 계획과 분리한다.
4. Qwen이 RESET_SESSION을 선택하면 쿠키·스토리지·브라우저 인증 정보를 이어받지 않은 새 세션에서 고정된 시작 URL을 한 번 연다. 초기 주소가 확인되기 전 일반 클릭·입력은 실행기가 차단한다.
5. 복구 후에도 주소가 다르거나 복구 판단을 받지 못하면 P/F를 내리지 않고 사유와 증거를 저장한다. 최초 URL 미확인 상태로 다음 TC들을 계속 수행하지 않는다.
6. 최초 URL 확인 후에는 TC의 정상적인 이동을 허용한다. 후속 TC는 기존 저장된 로그인 설정을 사용한다. 추가 증거 필요 등 브라우저를 열지 않은 항목은 최초 진입 확인을 소모하지 않는다.

인증 상태는 코드가 확인한 AUTHENTICATED_BY_SETUP, 로그인 입력 화면 관찰 LOGIN_FORM_OBSERVED, 그 외 UNKNOWN으로 구분한다. URL·초기 상태와 세션 복구 조작을 증거로 보존하며 초기화 조작은 시험 수행으로 계산하지 않는다.

이번 변경은 최초 진입만 보완한다. 로그인 TC 전체의 인증 전용 입력·계정 정책별 세션과 범용 Qwen 계획의 장시간 지연은 별도 보완 대상이다.
