# 반복 수집 중단 재현과 사유 표시

## 실제 확인

실패 작업 92fc646a-d647-4b3d-9220-71d7307603b3은 3개 화면 저장 후 메뉴 → Jobs에서 CRAWL_FAILED로 종료했다. 인증서 예외는 true였고 연결·로그인 테스트는 성공했다.

저장된 설정으로 같은 사이트에 읽기 전용 수집을 수행했다. 호스트 브라우저는 기존 중단 지점을 통과했지만 실제 Linux 수집기에서는 chrome-error: 주소를 normalizedUrl로 변환하면서 CRAWL_SCOPE_INVALID를 발생시키는 것을 재현했다. agent가 이 예외를 일반 CRAWL_FAILED로 축약해 UI에서 원인을 알 수 없었다.

첫 수정 후에는 5개 캡처 뒤 page.screenshot에서 Execution context was destroyed가 발생하는 후속 중단도 재현했다. 오류 원문·계정·토큰을 출력하지 않고 예외 위치와 알려진 유형으로 분류했다.

## 변경

- URL 정규화 전에 허용된 HTTP 화면인지 확인한다. 브라우저 오류 페이지나 범위 이탈은 실패 메뉴·사유로 기록하고 다음 메뉴로 진행한다.
- 메인 문서 requestfailed의 net::ERR_* 코드만 수집해 오류 페이지 사유에 연결한다. URL 쿼리·인증 정보는 기록하지 않는다.
- chrome-error 페이지에서는 전체 로딩 대기 시간을 소모하지 않는다.
- 스크린샷 중 컨텍스트 소멸·프레임 분리·전환·타임아웃은 CAPTURE_CONTEXT_CHANGED/CAPTURE_TIMEOUT으로 기록한다. 이전 화면의 증거를 다른 화면 스크린샷과 섞거나 마스킹 없이 저장하지 않는다. 해당 항목은 미완료로 남긴다.
- 콜백 저장 실패·인증 실패 등 다른 오류를 일괄 무시하지 않는다.
- 직전 화면 전환 때문에 시작 URL의 GET 이동이 중단되면 원래 화면별 대기 한도 안에서 한 번만 재시도한다. 회복한 이동은 실패로 집계하지 않는다.
- UI 진행 카드에 실패 코드와 마지막 진행 위치를 표시한다. CRAWL_FAILED만 저장된 과거 기록은 구체적인 원인이 기록되지 않았음을 명시한다. 완료 결과의 skipped 목록에는 메뉴별 사유를 펼쳐 보여준다.

## 검증

- 실제 브라우저를 사용한 개별 비HTTP 이동 실패와 캡처 컨텍스트 소멸 주입 시험을 추가했다. 다른 메뉴 진행, 미완료 유지, 마스킹 유지, 잘못된 캡처 미저장을 확인했다.
- 기존 로그인·쓰기 차단·재개·프레임/탭 시험을 포함한 8개 테스트 통과.
- UI 회귀에서 진행 카드의 실패 사유·마지막 위치 및 메뉴별 실패 목록 표시 확인. 프런트 빌드 통과.
- 실제 Linux 재시험은 읽기 전용으로 150초 한도를 사용한다. 이 시험으로 전체 메뉴 수집 완료나 대상 제품 기능의 정상 동작을 주장하지 않는다. 기존 작업과 저장 화면은 다시 쓰지 않는다.

## 최종 진단시험

수정 전에는 3개 캡처 후 CRAWL_SCOPE_INVALID로 종료했다. 첫 보완 후에는 5개 뒤 캡처 컨텍스트 소멸을 재현했다. 이동 중단 재시도까지 반영한 최종 Linux 시험은 16개 캡처, TIME_LIMIT(150초), coverageStatus=INCOMPLETE로 종료했다. 기록된 미완료는 Jobs의 CAPTURE_CONTEXT_CHANGED와 프로필 메뉴의 SOURCE_LOAD_TIMEOUT 두 건이며, 시간 한도 때문에 아직 탐색하지 못한 항목도 있을 수 있다. 전체 수집 완료가 아니다.

진단 스크립트는 캡처 콜백을 메모리에서 집계하며 기존 문서 세트에 화면·작업 결과를 추가 저장하지 않는다. 인증 정보는 메모리와 프로세스 표준입력에서만 사용한다. 일반 서비스는 재시작 후 수정된 실행기로 다음 실제 수집·재개를 수행한다.
