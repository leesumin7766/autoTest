# 개발 계획 — 2026-10-22

dev5의 2026-10-22 개발 변경을 반영했습니다. 기능 요약은 [README](../README.md), 실행 계약·검증은 [TEST_EXECUTION_DEV5.md](TEST_EXECUTION_DEV5.md)를 참고합니다. 체크된 항목은 검증한 구현 범위이며, 나머지 완료 기준과 운영 배포는 별도입니다.

## 합의한 방향

- 처리 시간보다 충분한 시험 수행을 우선한다. 속도 때문에 관찰·검증을 생략하지 않는다.
- 최우선 실패는 **F여야 할 항목을 P로 확정하는 것**이다. 높은 confidence만으로 통과를 보장하지 않는다.
- 반복 클릭·탐색·일부 미판정은 허용하되, 재시도가 첫 실패를 가리거나 데이터·다음 시험을 오염시키지 않게 한다.
- 사용자가 최종 결과를 다시 검토한다. 미판정이 과도하게 쌓이지 않도록 누락 입력·조작 오류·증거 부족·판정 불확실성을 구분한다.
- 로컬 Qwen으로 계획, Jev로 판단한다. 외부 생성형 LLM은 실제 결과를 확인한 뒤 도입을 검토한다.
- **사전 필요 파일·폴더 업로드는 후속 보관 항목**이다. 실행 전 업로드해 공급하는 구상만 기록하고 지금 구현하지 않는다.

## 1. TC별 기대 조건과 증거

각 TC를 새 세션에서 수행하고 caseId와 증거 번호를 분리한다. 기능별 조작 결과를 여러 TC에 함께 제공하지 않는다.

- [ ] TC마다 전제·대상·필요 동작·기대 조건·관찰 방법을 구조화한다.
- [ ] 기능 ID·전체 경로를 유지하고 같은 경로의 다른 기능을 합치지 않는다. 5depth 공란은 마지막 유효 기능으로 연결한다.
- [ ] 공유 가능한 증거와 별도 정상/경계/취소 시험이 필요한 증거를 구분한다.
- [x] 조건을 실제 수행·관찰과 연결하고 미수행 조건은 미판정으로 남긴다.
- [x] 원문·생성 계획·결함 예시를 실제 실행 증거로 쓰지 않는다.

완료 기준: 기능 하나가 성공해도 안내·취소·입력 제한 등 미수행 TC는 자동 P가 되지 않는다.
