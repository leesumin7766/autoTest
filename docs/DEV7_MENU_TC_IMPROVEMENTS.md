# dev7 메뉴트리·TC 생성 개선 및 검증

## 변경 범위

- 메뉴트리 공통 지침 `self-llm-v4`: 동일 조회 기능의 확인된 지표를 생략하지 않고 설명에 명시한다. 독립 등록·수정·삭제를 관리 한 행으로 합치지 않으며 같은 실제 메뉴 경로의 5depth 기능으로 분리한다. 기존 경로·JSON 구조는 유지한다.
- 제품별 프롬프트에 공통 규칙 본문을 중복하지 않는다. 프런트·서버의 지침 버전을 함께 변경했다. 사용자가 외부 LLM에 등록한 공통 지침은 v4로 교체해야 한다. 기존 승인 메뉴트리를 자동으로 다시 작성하지 않는다.
- TC 템플릿 `menu-tc-v3`와 로그인 27·주요/부가 9·CRUD 16·공통/문서 68개 정책을 유지한다.
- 절차 작성 버전 `procedure-v1.1`: 시나리오는 대상과 시험 목적, 입력 열은 사전조건과 번호별 수행 절차, 기대 출력은 번호별 관찰·비교 항목으로 작성한다. 기존 16개 TC 열과 실행 정보 20개 열을 유지한다.
- 등록·수정·삭제는 재조회 및 대상 외 데이터 유지, 취소는 원본 유지, 필수값·경계값은 저장 거부를 검증한다. 로그인 잠금은 잘못된 입력과 제출을 매회 수행하며 문서의 실패 횟수만 사용한다. 첨부 예시의 제품명·임의 정책·버튼·URL을 복사하지 않는다.
- 사람용 절차와 실행 정보의 단계·기대 출력이 연결된다. 선택자·실제 입력값·기대값의 연결이 없으면 `NEEDS_CONTEXT/UNRESOLVED`를 유지한다. P/F/N/A는 생성 단계에서 채우지 않는다.
- 원본 템플릿은 `templateOriginal`로 보존한다. 절차 버전을 생성 digest에 포함해 같은 메뉴트리라도 이전 생성본 캐시를 재사용하지 않는다.

## 검증

- Java 15개 테스트 통과: 생성기 7, 절차 작성 3, 인증 3, 외부 JSON 계약 1, 격리 `autotest_test` DB API 통합 1.
- 통합 검증: JSON/Excel 메뉴 업로드 → TC 생성 → 멱등성 → 다운로드 → 시험 준비 스냅샷 및 변경 감지.
- 기존 조회 기능의 자동 CRUD 분류에 맞게 오래된 테스트 기대값을 정정했다: 단일 조회 84개, 로그인 추가 시 111개. 명시적으로 부가기능을 지정한 경로는 77개를 유지한다.
- 프런트 TypeScript/Vite 빌드 통과.
- 기존 샘플 네 제품 1,283 / 842 / 1,670 / 671개, 총 4,466개 생성. 전체 원본 기능의 포함, 중복 ID 없음, 결과 공란, Excel 열·시트 및 검증 목록 유지 확인.
- 서버 반영 후 기존 NeoFlow 승인 메뉴트리로 API 재생성: 413개. 로그인 1·CRUD 12·주요기능 14개와 공통/문서 68개. 절차 버전과 Excel 내용을 확인한다.

## 남은 한계

- 기존 메뉴트리의 메뉴 미배치 기능 57개는 그대로다. 지침 변경만으로 현재 승인본의 분리·배치가 바뀌지는 않는다. 외부 LLM 재작성·검토가 필요하다.
- 기존 NeoFlow 메뉴의 복합 관리 기능은 그대로 유지한다. 이번 산출물 비교는 동일한 승인 메뉴트리를 입력으로 사용한다.
- 구조화된 절차는 실행 가능한 선택자·정확한 시험값이 확정된 스크립트가 아니다. 포괄적 기능, 암호화 저장, 문서·성능 등 일부 항목은 근거·도구 또는 사람이 추가로 구체화해야 한다.
- 실제 제품에 대해 413개 Playwright 시험을 실행하거나 결함 탐지 정확도를 입증한 결과가 아니다. 이번 검증은 생성 로직·API 연결·산출물에 한정한다.
