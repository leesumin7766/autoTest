# 시험 준비 분류와 수행 실적 UI 분리

대상 준비 이력: 2c2135b6-a48b-4f8a-bba0-dbe35cbf383b. 총 1,265건, 기능 133개와 공통·문서 3개 그룹. 상태 PREPARED, 시작 시각·수행 증거 없음.

## 변경

- 서버의 기존 completedCount는 PENDING 이외의 상태를 집계해 입력 부족 89건까지 포함했다. UI 수행률에는 이 필드를 사용하지 않고 TC 수행 완료(COMPLETED)만 집계한다. 기존 저장 데이터 수정이나 이력 삭제는 하지 않는다.
- 전체 1,265건을 실행 대기 1,176·사전 입력/환경 필요 21·별도 수행 필요 68·수행 완료 0·수행 오류 0·실행 제외 0으로 나눠 표시한다.
- 실제 수행 완료 0 / 전체 1,265, 0%를 표시한다. 실행 전 소요 시간은 0이다. 입력 부족·별도 수행·실행 제외를 수행 완료로 세지 않는다.
- 준비 이력의 '준비 완료'를 '실행 전 · 항목 확인'으로 변경한다. 시작 전 '이어서 준비 가능'과 완료 후 판정 검토 안내·이어하기 버튼은 표시하지 않는다. 준비 상태의 중단 버튼은 '준비 취소'로 표시한다.
- 항목별 필터로 대기/입력·환경/별도 수행/수행 완료/오류/제외 목록을 확인한다. 상세 화면은 미수행 항목을 Jev 판정처럼 표시하지 않고 준비 상태와 사유를 표시한다. 결과가 없는 미수행 행은 '판정 전'으로 표시한다.
- 실행 이후에는 기존 이어하기와 판정 결과·검토 건수를 표시한다. 대기와 재준비 대상은 모든 입력이 확정됐다는 의미가 아님을 명시한다.

## 검증

- 실제 1,265건 준비 이력을 GET 요청만으로 열어 카운터·수행률 0·시간 0·필터·상세 사유·이어하기 숨김을 확인했다. 시험 실행 요청은 하지 않았다.
- 기존 수집 시간·중단·재개·모바일 UI 회귀 검증 통과. RunProgress의 기본 수집 표시 형식은 유지했다.
- TypeScript/Vite 빌드 검증. 변경 화면은 output/test-execution/preparation-summary.png에 보존.
- 현재 4173 프런트엔드에 반영. 백엔드 시험 시작·준비 데이터 변경은 하지 않았다.
