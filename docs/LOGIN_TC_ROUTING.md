# 로그인 TC와 로그인 화면 경로

로그인은 사이드바 메뉴가 아니라 인증 진입점이다. 현재 메뉴에 로그인 행이 없거나 배치 필요로 남아 있어도 로그인 필요 설정 또는 문서 근거가 있으면 TC 생성에서 로그인 27개를 자동 추가한다. 기존 로그인 기능이 있으면 중복 추가하지 않는다.

## 인증 근거

- 수집과 연결된 메뉴: 해당 완료 수집의 접속 설정을 사용한다.
- 업로드 메뉴: 같은 문서 세트의 최신이며 stale이 아닌 접속 설정을 사용한다. 현재 문서 세트의 기능리스트·매뉴얼에서도 로그인과 잠금 정책 근거를 확인한다.
- 설정의 로그인 필요와 성공한 수집의 인증 확인은 구분한다. 설정만 있으면 `verifiedCrawlAuthentication=false`다.
- 다른 문서 세트의 접속 주소·계정은 자동으로 가져오지 않는다. 비밀번호·사용자명·쿠키는 TC 인증 컨텍스트에 복사하지 않는다.

## 경로 선택

메뉴트리 검토에서 로그인 기능의 배치 목록에는 `로그인 화면` 항목을 별도로 제공한다. 실제 웹 메뉴를 새로 만들지 않으며, 서버도 로그인 기능과 로그인 필요 근거가 있는 경우에만 인증 경로를 허용한다.

TC 검토에는 `기본 URL`과 `설정된 로그인 URL`을 선택하는 항목을 제공한다. 기본 주소에서 로그인하는 제품은 기본 URL을 선택하면 된다. 임의 외부 URL은 서버가 거부한다. 선택한 주소는 로그인 TC의 실행 대상에 반영된다. 주소를 변경하면 새 TC 초안을 생성해야 하며 기존 TC 세트는 자동 수정하지 않는다.

접속 설정이 없는 별도 업로드 세트는 문서 근거로 로그인 TC를 만들 수 있어도 URL을 알 수 없다. 이 경우 같은 세트에서 접속 설정을 저장한 뒤 다시 생성한다.

## 검증

기본/별도 로그인 URL, 설정만으로 자동 추가, 로그인 없음, 중복 방지, 비밀정보 비노출, 인증 경로와 일반 메뉴 분리, 업로드 메뉴→저장 접속 설정→로그인 TC 27개 추가, 허용하지 않은 URL 거부를 테스트한다. 브라우저 fixture에서도 사이드바 밖 경로 선택과 기본 URL 선택·생성 요청을 검증한다.
