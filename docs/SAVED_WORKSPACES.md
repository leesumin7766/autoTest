# 이름 있는 시험 작업 저장·불러오기 — 2026-10-28

## 저장 구조

하나의 시험 작업은 기존 문서 세트 UUID(submission_id)를 고유 ID로 사용한다. 파일을 별도 폴더에 복제하지 않고, 기존 자료·수집·메뉴트리·TC·시험 이력을 같은 ID 아래 묶는 논리적 저장 공간이다.

```text
시험 작업(UUID + 사용자 지정 이름)
  ├ 자료: submission_files + S3 원본
  ├ 접속 설정·화면 수집: playwright_crawl_setups/jobs/pages
  ├ 메뉴트리·검토/승인: functional_menu_jobs
  ├ TC 생성본: menu_tc_sets
  └ 시험·판정·증거: test_execution_runs/evidence
```

V26의 submission_workspaces는 이름·마지막 탭·수정 시각만 추가한다. 기존 산출물/ID/승인 상태를 덮어쓰거나 다시 생성하지 않는다. 기존 제출도 기본 이름 `시험 작업 <ID 앞 8자리>`로 등록하고 사용자 이름 변경을 지원한다. 부분 업로드/실패 작업도 불러와 기존 규칙에 따라 보완할 수 있다.

## 사용

1. 왼쪽 **시험 작업 이름**에 제품·버전 등을 입력하고 자료를 업로드한다. 첫 파일을 저장할 때 고유 ID와 이름이 등록된다.
2. 메뉴트리·TC·시험은 기존 흐름대로 수행한다. 각 산출물은 기존 DB/S3 저장 경로에 유지된다.
3. **저장된 시험 작업 불러오기**에서 이름·ID·자료/수집/메뉴/TC/시험 이력 수를 확인하고 선택한다. 최근 생성 시각부터 내림차순으로 20개씩 조회하며 이름 변경·탭 이동은 정렬에 영향을 주지 않는다.
4. 새로고침하면 현재 브라우저에서 마지막으로 선택한 작업을 자동으로 불러오고, 서버에 저장한 마지막 탭을 연다. 다른 브라우저에서는 저장 작업 목록 또는 ID 조회로 불러온다.
5. 기존 **문서 세트 ID → 세트 조회**도 유지한다. 이름은 **이름 저장**으로 변경한다.
6. **새 문서 세트**는 현재 선택만 해제한다. 이전 작업·산출물을 삭제하지 않는다.

각 단계는 자신의 기존 API로 저장 이력을 다시 읽는다. 기본은 해당 단계의 최신 저장 이력이며 과거 버전은 기존 이력 선택으로 확인한다. 새로고침이 시험을 새로 시작하거나, 완료된 산출물을 자동 재생성하지 않는다. 실행/수집 중이었다면 기존 서버 작업 상태를 조회한다.

저장하지 않은 편집 초안·파일 선택·복사 전 외부 LLM 응답은 복원 대상이 아니다. 브라우저에는 마지막 회원 식별값/선택 작업 ID만 저장하고 문서 본문·비밀번호·산출물 JSON을 넣지 않는다. 개발용 회원 식별값 저장은 실제 사용자 인증 기능이 아니다. 목록/메타데이터 API는 X-Member-Id 소유권을 확인한다.

기존 문서 검증·메뉴 승인·stale 검사·시험 준비 조건은 유지한다. 목록의 산출물 개수는 저장 이력이며 현재 승인/실행 가능 여부를 뜻하지 않는다.

## 코드·API

| 코드 | 책임 |
| --- | --- |
| SubmissionWorkspaceService | 소유자별 목록·요약·불러오기·이름/탭 부분 업데이트 |
| SubmissionWorkspaceController | 목록/메타데이터 HTTP API, no-store |
| SubmissionController | 첫 자료 등록 요청의 workspaceName 검증·등록 |
| SavedWorkspaces.tsx | 작업 이름·불러오기 팝업·페이지 이동·직접 ID 입력 |
| App.tsx | 저장 자료/검증 상태 복원·패널 전환·ID 기억·마지막 탭 저장·작업 간 상태 초기화 |
| V26 | 메타데이터 테이블, 기존 제출 등록, 이름/탭 제약 |

| Method | 경로 | 내용 |
| --- | --- | --- |
| GET | /api/submissions/workspaces?offset=0&limit=20 | 소유자별 목록·이력 수·hasMore. limit 1~50 |
| GET | /api/submissions/{id}/workspace | 소유권을 확인한 이름·제품 ID·마지막 탭·이력 수 |
| PATCH | /api/submissions/{id}/workspace | `{name?, lastPage?}`. 이름 1~120자, 탭 허용 목록 검사 |
| POST multipart | /api/submissions | 기존 입력에 선택 workspaceName 추가. 미지정 시 기본 이름 |

이름/탭 부분 업데이트는 제출 행 잠금으로 직렬화하고, 탭 저장이 기존 이름을 기본값으로 덮지 않도록 한다. 불러오기 요청을 취소/교체하면 이전 응답으로 현재 작업을 바꾸지 않는다. 불러오기 실패 시 기존 선택 작업을 보존한다.

- Node 24.21.0 프런트 빌드 통과.
- 진행 중 수집/시험 0건 확인 후 운영 DB custom-format 백업을 .runtime에 보존했다. V26 success와 기존 제출 66개/작업 등록 66개를 확인했다. 운영 데이터를 초기화하지 않았다.
- 5173이 다른 worktree의 이전 Vite를 제공하는 것을 발견해 현재 작업 버전으로 전환했다. 서버 JAR과 UI에 반영했다.
