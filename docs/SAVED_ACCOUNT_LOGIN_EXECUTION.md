# 정상 로그인 TC 실행

대상은 저장된 유효 계정으로 정상 로그인을 시험하는 LOGIN-04다. 잘못된 비밀번호·계정 잠금·권한별 시험에 정상 로그인 동작을 재사용하지 않는다.

1. 새 비로그인 세션에서 초기 화면을 준비한다. 정상 로그인 TC는 일반 기능의 사전 자동 로그인을 하지 않는다.
2. Qwen은 계정 값 대신 savedAccountAvailable/dedicatedLoginAllowed/loginAttempted만 받아 LOGIN_SAVED_ACCOUNT 또는 NEEDS_INPUT을 짧게 반환한다.
3. 실행기는 저장된 계정을 사용해 아이디·비밀번호 입력 후 한 번 제출한다. 기록은 USERNAME_FILLED/PASSWORD_FILLED/SUBMIT_ATTEMPTED/SUBMITTED/AUTHENTICATED로 남긴다. 자격증명은 모델 계획·조작 값에 넣지 않는다.
4. 입력 없는 일반 Login 클릭과 두 번째 저장 계정 로그인은 실행 전에 차단한다. 인증 전용 제출은 일반 변경 허용 설정과 분리하되 로그인 대상 원점·관찰된 인증 경로로 제한한다. 계정 입력 전과 비밀번호 입력 직전에 form action의 원점을 확인한다.
5. 로그인 조작 뒤에는 다시 계획을 만들거나 재로그인하지 않고 첫 결과를 판정한다. 실제 입력·제출 증거가 없으면 정상 로그인 수행으로 계산하지 않는다. 인증 성공 증거가 없으면 Jev가 P를 제안해도 미판정으로 되돌린다.
6. 입력 필드는 스크린샷에서 가리고 반환되는 텍스트·기록에서 비밀번호를 제거한다. 원본 TC 기대 조건 전체에 대한 검토는 유지하므로 로그인 성공만으로 별도 권한 검사까지 통과시키지 않는다.

검증 범위: 실제 Chromium 계정 입력/제출 1회, 빈 제출 및 반복 제출 차단, 비밀정보 비노출, 외부 form 전송 차단, 인증 거부 시 첫 응답 보존, 인증 미확정 시 P 차단, 기존 수집 로그인과 시험 실행 회귀.
