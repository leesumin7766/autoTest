# 기존 TC 양식 검토 및 개선 예시

## 검토한 산출물

- output/auth-improvements-20261023/NeoFlow-TC.xlsx: TestCase 671건, 16열. 실행 정보 12열. 생성 정보에 결함 열은 실제 발견 결함이 아닌 작성 예시라고 명시됨.
- outputs/sample3-e2e-20261022/04-TC.xlsx: 같은 TC 16열과 실행 정보 12열. 로그인 보강 전 산출물.

이 문서는 설계 제안이다. 원본 Excel과 생성·실행 코드는 변경하지 않았다.

## 결정 제안

TestCase의 기존 16열과 순서를 유지한다. 실행 정보도 기존 시트를 보강한다. 같은 목적의 실행 명세 시트를 추가로 만들지 않는다. 생성 정보는 유지한다. TC 내용이 변경되면 연결된 실행 정보의 검토 상태를 해제한다.

현재 TC의 대표적인 문제는 열 누락이 아니라 내용의 추상성이다. 최신 파일에서 기대 출력이 '기능이 목적에 맞게 동작함'인 행은 64건이고 결함 예시에 AAA가 포함된 행은 268건이다. 안내메시지·입력필드 등 조건부 시험 자체는 삭제하지 않는다. 적용 여부를 확인하고 비적용 근거가 있는 경우 N/A로 남긴다. 준비 정보 부족은 N/A가 아니다.

## 예시 1: 기존 Dashboard TC의 내용 보완

## 예시 2: 기존 로그인 TC의 내용 보완

최신 파일 TestCase 2행 TC-001-001 기준. 기존 기능구분·품질특성·하위특성을 유지한다.

|항목|현재|개선 예시|
|---|---|---|
|테스트 시나리오|유효한 아이디/비밀번호로 로그인되는지 확인|1. 로그아웃 상태의 로그인 화면 진입. 2. 저장된 유효 시험 계정의 ID·비밀번호 입력. 3. 로그인 1회 실행. 4. 로그인 후 대상 화면과 사용자 메뉴·해당 역할의 예상 메뉴 확인.|
|입력 (사전조건 포함)|로그인|활성·승인 완료·잠금 해제 계정. 역할과 예상 허용 메뉴 목록 확정. 기존 세션 없는 브라우저. ID·비밀번호는 저장된 인증 설정 참조.|
|기대 출력 (사후조건 포함)|유효한 아이디/비밀번호로 로그인되고 해당 권한에 해당하는 메뉴가 표시됨|로그인 폼이 사라지고 로그인 후 화면 본문과 해당 사용자 메뉴가 표시됨. 예상 허용 메뉴가 표시됨. 브라우저가 인증된 상태로 대상 화면을 조회할 수 있음. 서버 내부 토큰 값 자체를 Excel에 기록하지 않음.|
|결함요약 (예시)|로그인 오류|유효한 계정의 로그인 실패 또는 역할별 메뉴 불일치|
|결함정도 (예시)|H|H: 기존 참고값 유지|
|결함내용 (예시)|관리자 계정 로그인 후 진행 상태로 남아 로그인되지 않음|활성·승인 완료·잠금 해제 계정으로 로그인했으나 제한 시간 내 대상 화면에 진입하지 못하거나 예상 허용 메뉴가 누락됨. 입력 비밀번호는 결함 증거에 포함하지 않음.|

이 시트에 추가할 의미 정보는 TC/명세 버전, 시험 데이터 참조, 구조화된 실행 단계, 조건별 검증 기준, 제한 시간·재시도 정책, 증거 수집, 정리·복구, 자동화 방식이다. Excel은 검토 표현이고 실제 실행은 같은 구조화 데이터를 사용한다. 명세는 TC 요구사항을 축소하거나 새로운 제품 요구사항을 발명할 수 없다.

Dashboard 예시에서 실행 준비는 '준비 필요: 동일 시점·범위의 KPI 정답 자료 미연결'이다. 화면에 KPI가 보였다는 이유만으로 전체 TC를 준비 완료나 P로 바꾸지 않는다. 단순 표시 검증과 수치 정확성 검증을 별도 TC로 분리하는 경우에는 원 TC와의 관계를 유지하고 요구사항 전체를 빠짐없이 배분해야 한다.
