# dev5 — 로컬 Qwen + Jev 실행 프로토타입

2026-10-22 단계 간 연결·배포 수정 및 실제 준비 화면 검증은 [연결 점검](PIPELINE_AUDIT_2026-10-22.md)을 참고한다. 현재 서버의 653개 TC와 이전 검증 Excel의 671개 TC는 별도 자료다.

최신 우선순위·완료 기준은 [개발 계획](DEVELOPMENT_PLAN.md)을 따른다. 속도보다 충분한 수행과 F→P 오판 방지를 우선하며, 사전 필요 파일·폴더 업로드는 후속 보관 항목이다. 아래 구현 설명과 개선 계획을 구분한다.

## 흐름

최신 수행 계약: 메뉴 이동은 crawler가 탐색으로 표시하며 실제 시험 조작으로 세지 않는다. 계획은 최대 12회/TC 900초이며, 실제 동작과 명시적 FINISH 이후에만 판정한다. 기대 결과의 설명형 문장은 요구별 SEMANTIC 조건으로 변환한다. 화면은 네트워크·본문 안정·로딩 종료를 기다린다. 고정 progressbar는 로딩이 아니다. 파일 공급/공통 시험은 미수행으로 분리한다. 증거는 V25 별도 테이블과 회원 소유권 검사 상세 API를 사용한다. 접속 설정이 준비 이후 바뀌면 재준비가 필요하다.

05의 Test connection 팝업에서 `로그인 필요`를 선택하면 일반 로그인 또는 Basic 인증의 아이디·비밀번호를 입력해 LOGIN 검사를 수행한다. 같은 사이트의 기존 설정을 불러오고, 저장된 비밀번호는 재입력 없이 재사용할 수 있다. 로그인 성공 근거가 없는 HTTP 200은 로그인 성공으로 표시하지 않는다. 미선택 시 CONNECTION 접속 검사만 수행한다. 성공한 설정만 저장하며 실제 TC 실행에서 같은 설정과 암호화된 비밀번호를 사용한다. 실패 시 기존 설정을 덮지 않는다. 실제 NeoFlow 계정 로그인·저장과 비밀번호 미노출을 확인했고 TC 자체는 이 검사에서 실행하지 않았다.

TC 선택 → 실행 snapshot → 대기 작업 claim → 기능별 문서 구간·화면 관찰 → 로컬 Qwen 계획 → Playwright 수행 → Jev 판정 → 실행 이력 저장.

- Qwen: Ollama `qwen3:8b`, JSON schema로 제한된 조작 배치 생성. 외부 생성형 LLM fallback 없음.
- Playwright: 실제 관찰된 요소 ID만 클릭·입력·선택. 관찰된 같은 출처 링크로 이동. 임의 JS·명령 실행·임의 파일 경로 불허.
- Jev: 실제 화면 텍스트·수행 기록과 TC를 비교. P/F/N_A/INSUFFICIENT 중 선택. 기본 confidence 0.9 미만은 미판정 유지. confidence는 실측 정확도 수치가 아님.
- Jev는 기존과 같이 외부 TypeSafe API를 사용한다. 전체 구성이 완전한 오프라인 실행은 아니다. 계정 비밀번호는 Qwen/Jev에 전달하지 않는다.

화면 변경 이벤트마다 Qwen을 호출하지 않는다. 조작 배치 뒤 관찰로 다음 절차를 계획하며 실제 시험 동작과 명시적 FINISH 뒤 판정한다. 최대 12배치·배치당 8조작, 계획 호출 600초·TC 전체 900초로 제한한다. 기대 결과를 얻으려고 같은 제출을 반복하도록 맡기지 않는다. 실제 sample3에서는 과도한 입력과 반복 메뉴 탐색 때문에 시간 한도에 걸렸다. [실물 흐름 보고서](SAMPLE3_E2E_2026-10-22.md)의 결과를 프로토타입 성공 범위와 구분한다.

## 구현 위치

- TMS `TestExecutionWorker`: 단일 로컬 워커, V24 상태/attempt 저장, 기능별 결과 저장, 취소·늦은 응답 fencing. 긴 HTTP는 별도 실행 스레드에서 처리하여 기존 scheduler를 막지 않음.
- AI `test_execution.py`: `/api/v1/test-executions/feature`, `/capabilities`. 기존 내부 토큰 인증. 실제 모델 호출과 테스트용 의존성 주입을 구분.
- Crawler `tc-execution.js`: 인증된 `/api/v1/tc-browser/open`, `/{session}/step|close`. 화면 수집과 로컬 브라우저 busy 슬롯 공유. 세션 미사용 10분 만료.
- UI: 자동 진행 조회, P/F/N/A/미판정 수, 현재 기능, 실제 텍스트·스크린샷·실행 계획 확인. 준비 snapshot에서 데이터 변경 허용 여부를 고정.

실제 실행 워커는 이번 단계에서 기존 TMS에 연결했다. 빈 test-execution-service로 분리하는 것은 기능이 안정화된 뒤 가능하다. 워커는 단일 TMS 인스턴스를 가정하며 서버 시작 시 RUNNING 이력을 INTERRUPTED로 닫는다. 종료 실행은 새 준비로 재시험한다. 원본 TC 결과는 수정하지 않는다.

기존 화면 수집 로그인 설정은 정확히 같은 targetUrl일 때만 재사용한다. 없으면 로그인 없는 접근으로 시작한다. 수동/SSO 로그인은 미지원이다. 문서는 기능명과 일치하는 구간을 출처·문자 위치와 함께 제공하며 전체 문서 분석을 했다고 주장하지 않는다.

## 현재 제약

- 파일 업로드용 실제 시험 파일 전달, iframe 내부 조작, 네이티브 앱, 확인/입력 팝업 응답은 후속이다. 필요한 경우 NEEDS_CONTEXT로 남기고 F로 오인하지 않는다.
- CSV/TXT/JSON/TSV는 최대 1MiB의 실제 내용·SHA256을 수집한다. DOWNLOAD_TEXT 조건은 잘리지 않은 완료 파일의 내용을 비교한다. 바이너리·대용량 파일의 내용 검증은 후속이다.
- 데이터 변경 비허용 시 POST 등 변경 가능 요청을 막는다. 조회에 POST를 쓰는 제품도 실행 제약으로 남을 수 있다.
- 공통·문서 시험은 별도 수행 방식이 필요하므로 미판정으로 보존한다.
- Jev에 이미지는 보내지 않는다. 스크린샷은 사용자가 검토하는 증거이고 판정은 DOM 텍스트·동작 기록 기반이다. 그래프/시각 품질의 자동 판정은 미지원이다.
- 부족한 전제나 조작 오류를 N/A/F로 치환하지 않는다. 실행 오류, 정보 부족, 낮은 판정 confidence를 별도로 표시한다.
- 실행 중인 각 조작을 즉시 강제 종료하지는 않는다. 취소는 다음 조작 배치 전에 검사하고, 취소 후 도착한 결과는 DB에 반영하지 않는다.

## 실제 모델 시험 (2026-10-22)

실제 사용자 제품을 변경하지 않고 별도 포트 8017의 합성 사이트에서 시험했다. AI 서비스가 다른 worktree를 마운트하고 있어 dev5 코드는 `/tmp/execution-dev5`의 격리된 Python 프로세스로 실행했다. 운영 AI 소스나 모델 설정은 변경하지 않았다.

위 경로 설명은 합성 검증 당시 상태다. 이후 2026-10-22 사용자의 서버 반영 승인으로 DB 백업 후 V24를 적용하고 TMS·AI·crawler를 갱신했다. AI mount를 현재 작업 폴더로 맞추고 Qwen 모델·Jev 설정·내부 인증·API 연결을 확인했다. 실제 제품 전체 시험 완료를 확인한 것은 아니다.

| 시험 | 결과 | 소요 시간 |
| --- | --- | --- |
| 정상 저장 후 ‘저장 완료’ | P, confidence 0.95 | 11.50초 |
| 저장 버튼이 서버 오류 문구 표시 | F, confidence 0.96 | 6.46초 |

파일 입력 제약을 일반 ERROR 대신 NEEDS_CONTEXT로 구분한 뒤 재시험했다. Qwen은 여전히 파일 선택을 시도했으나 실행기가 차단하고 미판정·추가 정보 필요를 유지했다(6.07초, `live-missing.json`). 모델이 누락 전제를 정확하게 이해했다고 해석하면 안 된다.

초기 Qwen 계획은 확인할 결과를 누락 입력으로 오해했고, 이후에는 완료 후 같은 버튼을 반복 클릭했다. 실행/완료/입력 대기와 이동/시험 단계를 명시적으로 구분하고 TEST 배치 후 프로그램이 판정으로 전환하도록 수정했다.

저장 사례 두 건은 구별했지만 추가 조회 사례는 confidence 기준을 충족하지 못했다. 이를 통과시키려고 기준을 낮추지 않았다. 이 결과는 NeoFlow 전체 671개 TC 자동화의 정확도를 증명하지 않는다. 실제 제품 일부 기능으로 품질을 더 확인한 뒤 모델 크기·계획 방식·판정 질문 분해를 개선하고 외부 LLM 도입 여부를 결정한다.

자동 테스트: 실제 Playwright 제약 검사, AI의 조작 실패/취소/낮은 신뢰도 처리, 격리 DB의 워커 claim·결과 저장·상태 전이, 기존 화면 회귀 테스트. 합성 결과 파일은 `output/test-execution/live-*.json`에 보존한다.

## 신뢰성·검토 기능 추가 (2026-10-22, 미배포 개발 변경)

- 각 TC를 독립 브라우저 세션으로 수행·저장하며 증거 ID에 caseId를 연결한다. 기능 하나의 성공으로 다른 TC가 통과하지 않는다.
- 기대 원문에서 확인 조건을 만들고, 로컬 모델 스키마에서 원문 인용·확인값을 제한한다. 프로그램이 조건 전체의 원문 연결·실제 조작·문구/값/파일 내용·재조회 근거를 검사한다. Jev는 TC 판정 외에 대상 식별·전체 수행·의미 조건을 답한다. 기본 0.9 기준은 유지한다.
- 반복 쓰기 클릭은 첫 관찰을 보존하고 차단한다. 같은 TC의 이전 F가 있으면 새 성공도 자동 P로 확정하지 않는다. 데이터 생성·삭제 전후의 완전한 격리·정리 도구는 아직 없다.
- 06/07에서 실행별 증거와 기대/실제 결과를 확인하고 사유를 남겨 판정을 수정한다. 자동 결과·수정 전후·담당자·시각·revision을 보존하고 동시 수정 충돌 및 다른 소유자 접근을 차단한다. 결함 후보 확정/기각/추가 시험 상태를 저장한다.
- 제품/패치 버전을 붙여 선택 항목 또는 F·미판정을 새 실행으로 준비한다. 실제 시작은 05에서 별도로 한다. 이전 실패를 연결하며 Markdown 보고서는 초안이다. 기업 서식·버전 비교 화면·재현 절차 편집은 후속이다.
- 새 테이블·마이그레이션 없이 기존 실행 snapshot을 사용했다. 소스 변경을 운영 서버 반영 완료로 간주하지 않는다.

### 실제 NeoFlow 조회 검증

사용자가 지정한 sample/sample3의 Server 사용자매뉴얼 v1.0.3·기능리스트 v1.0.3과 기존 TC Excel의 TC-002-001(Job 목록 조회), TC-013-001(DAG 조회)을 사용했다. 처음 접속은 ERR_CERT_AUTHORITY_INVALID로 실패했다. 사용자의 명시적 허용 후 해당 개발 서버의 임시 세션에만 인증서 예외를 적용했고 로그인·읽기 전용 수행을 완료했다. 실제 데이터 등록·수정·삭제·작업 실행은 허용하지 않았다. 자격 증명을 소스·모델 입력·결과 파일에 저장하지 않았다.

| TC | 실제 결과 | 판정 confidence | 소요 시간 |
| --- | --- | --- | --- |
| TC-002-001 Job 목록 조회 | 미판정, NEEDS_REVIEW | INSUFFICIENT .51 | 128.27초 |
| TC-013-001 DAG 조회 | 미판정, NEEDS_REVIEW | INSUFFICIENT .51 | 127.15초 |

두 건 모두 계획 1회·증거 3건이다. Qwen이 입력의 기능 설명을 화면에 그대로 표시될 문구로 선택해 조건 검사가 맞지 않았다. 단순 화면 이동으로 상태·카테고리·정렬 조회를 모두 입증하지 못했으며 P/F를 확정하지 않았다. 실제 제품 결함 발견 또는 전체 671 TC 검증 성공으로 설명할 수 없다. source 문서를 구체적인 조작·의미 조건으로 분해하고 TC 범위 전체를 수행하는 계획 보완이 다음 우선순위다. 결과는 `output/test-execution/neoflow-readonly.json`에 별도 보존했다.

## 반영 조건

### 소요 시간·현재 단계·미완료 이어가기

05는 실행 대기, 브라우저 접속, Qwen 계획, Playwright 조작, 재조회, Jev 판정 단계를 표시한다. 내부 progress API는 토큰·run·attempt·RUNNING 상태를 검사하며 중단/이전 시도의 갱신을 거절한다. 종료 시각을 고정하여 나중에 사용자 검토를 저장해도 소요 시간이 늘어나지 않는다. 상태 표시의 일시적 전송 실패는 결과를 버리는 사유로 쓰지 않는다.

`POST .../executions/{run}/resume`은 종료된 실행에서 미완료 브라우저 TC만 골라 새 PREPARED 실행을 만든다. 기존 결과·증거·판정 수정 이력을 보존하고 원본 실행을 연결한다. 완료된 미판정은 자동 재수행하지 않으며 검토/선택 재시험을 사용한다. 공통·문서 시험은 실행 방식 보완 대상이다. 데이터 변경 허용 시 중단 당시 현재 TC와 오류/정보 부족 TC는 반영 여부가 불확실하므로 자동 반복하지 않고 resumeNeedsReview에 남긴다. 남은 TC 준비 뒤 실행 요청으로 시작한다.

02의 화면 이어서 수집 계약은 REMOTE_CRAWL_AGENT.md를 따른다. 실제 브라우저의 화면 수 한도 중단→재개, 격리 DB의 캡처·TC 결과 보존과 이전 claim/attempt 거절, 실시간 시계·종료 고정·모바일 표시를 검증했다. 원격 실행기의 재개 capability를 확인하며 구형 실행기는 업데이트 안내와 함께 거절한다. 운영 배포는 별도다.

운영 V24 적용 전 DB 백업. TMS bootJar와 crawler 재빌드·재시작, AI source mount를 현재 dev5 작업 폴더로 맞춘 뒤 재시작 필요. 현재 실행 중 서비스에 자동 반영했다고 가정하면 안 된다. 운영 컨테이너 반영은 별도 승인 후 수행한다.

위 절차에 따른 2026-10-22 서버 반영은 완료됐다. 다음 변경을 반영할 때도 소스·실행 경로·이미지·마이그레이션을 별도로 확인한다. 개발 계획에 적힌 미구현 항목까지 배포됐다는 의미는 아니다.

환경 선택: `EXECUTION_QWEN_MODEL` 기본 qwen3:8b, `OLLAMA_BASE_URL`, `CRAWLER_SERVICE_URL`, `MANAGEMENT_SERVICE_URL`, `TYPESAFE_API_KEY`, `PRODUCT_DESCRIPTION_INTERNAL_TOKEN`. `EXECUTION_JEV_MIN_CONFIDENCE` 기본 .9. 테스트에서는 `execution.worker.enabled=false`로 scheduler를 막고 동기 워커 저장 검증을 별도로 수행한다.
